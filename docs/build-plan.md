# SKALD Accessibility — Remediation Build Plan

Date: 2026-08-16. Status: **PROPOSED — awaiting owner rulings; no code changed.** Companion to `ARCHITECTURE_REVIEW_2026-08-16.md` (the assessment this plan remediates). Baseline standard: Citizen Speaker / Sleeptalker / Vantage (the approved OAG architecture). Owner directions already given and honored throughout: hook the UI we have; rely on native controller focus; ditch unnecessary polling; integrate Tolk in place of raw NVDA.

## 0. Doctrine

Keep the hooks we have — they are mostly on the right methods — and change what they *do*: hooks note, one end-of-frame drain reads and speaks. Selection truth is the game's own field, read at the game's own write point. Per-frame polling is eliminated entirely; the only "polls" that remain are settled truth-reads at the drain clock, triggered by events — the framework's "events for transitions, polls for truth" in its sanctioned form. One clarification that governs several packages: a *single last-spoken record compared at the drain clock* is the sanctioned diff-at-clock engine (the OAG updateUI model); what the standard bans is the scattered per-hook version — per-hook dedup dictionaries, init-suppression windows, first-value swallows, and manual cache clearing. The end state of this plan is that every one of those is deleted, and deletability is the acceptance test that the joins are right.

## 1. The selection join (verified against the decompile, 2026-08-16)

`UICanvas.setCurrentSelectedButton(int)` (UICanvas.cs line 91) is a trivial private setter, and `UIButtonControlBase : UICanvas : UIElement` — so **every button control inherits one universal selection write point**. Confirmed writers all funnel through it: the mod's increment/decrement prefixes, `setCurrentSelectedButtonIndexToHoveredElement()` (hover→selection sync, also called by `UIInventorySheetBase`), `boundCurrentSelectedButtons()` clamping, screen-init reset, and the grid screens (`UIAbilitySelectorGrid`, `UIInventorySheetBase`). A note-only postfix here — instance + new index into a pending slot, latest-wins — hears every selection change from every path, including ones the foundered mod's mirror missed by construction. The drain then reads `getCurrentSelectedButtonIndex()` and the scrollable list *after* the game has finished the frame's writes, so set-then-clamp sequences resolve to the final value automatically.

Known open edge, entered on the gap ledger rather than solved speculatively: pure-hover mouse movement that changes `hoverIndex` without writing the selection index (mouse-only browsing). The keyboard path never hits it; a mouse-parity ruling can add a hover join later.

**Owner design ruling honored: native focus without controller spoofing.** The March design — remove `isControllerConnected()` gates piecemeal rather than forcing controller mode, because spoofing changes combat behavior/labels/glyphs — is owner-authored and stays. "Rely on native controller focus" here means: the game's `currentSelectedButton` is the *only* selection truth and the mod's `NavigationCursor` mirror is deleted. (If the combat-glyph concern is ever disproven live, flipping to Vantage-style forced controller mode is a compatible future move; nothing in this plan blocks it.)

## 2. Target architecture

Three tiers under `src\`, single composition root — the lineage layout at minimal scale:

- **`src\Scaffold\`** (game-agnostic, ported): `Tolk.cs` — P/Invoke wrapper (cdecl, wide strings; `Tolk_TrySAPI(true)` + `Tolk_PreferSAPI(false)` so the screen reader is preferred with SAPI fallback; `DllNotFoundException` → log-only mode, never a crash). `SpeechService.cs` — ported from Sleeptalker: Immediate (interrupts, preserves queue) vs Queued priorities; paced pump (`Tick()` dequeues only when `Tolk_IsSpeaking()` is false and ≥0.15s since last emit; cap 20 with loud drop logging); explicit `FlushQueue`/`FlushSource` (flushing is an act, never a side effect); per-utterance source tags; 200-entry history ring (replay reads the ring without re-adding — the history self-corruption bug dies by design); central `Clean` (transcode, don't strip — absorbs the current `CleanText`, keeping SKALD's `#c=`/`{script}` tables); every emit logged `[Speech:<source>]` before Tolk so the log is a full transcript. `Pump.cs` — pending-slot spine below.
- **`src\Skald\`** (game-specific): the patch classes (note-only), the drain composition (button labels, trailing "N of M" per the positional-counts rule, feat-node name fallback, `getControllerScrollableList` logic from the March diff), the state reader, input handling.
- **`Plugin.cs`** — composition root only.

**The pump:** hooks call `Pump.Note*(...)` and return. One drain per frame — `LateUpdate` on the plugin (SKALD demonstrably does not destroy the plugin object; five sessions ran off `Plugin.Update`), frame-guarded, wrapped in one try/catch that logs (the pump never dies — the current poller's kill-switch class of failure becomes impossible). Drain order encodes precedence: state transition → popup → selection → content diffs → slider → combat-log batch → barks → `Speech.Tick()`. Pending model: one nullable slot per stream, latest-wins, cleared on read; combat log and barks accumulate in per-frame batch lists and coalesce (compress, don't curate — "and N more" summarization, never dropped categories).

## 6. Coverage annex (2026-08-16 full-decomp survey; definitive, supersedes the March tier list)

Ground truths that shape the remaining work. Full map in the memory store (`reference_controller_coverage.md`).

- **Native "focus" is a controller-gated virtual-mouse snapper.** Index navigation exists only for controller input; keyboard users natively have number keys 1–9, hotkeys, and the mouse. The SkaldIO gate-removal layer is therefore not an enhancement but the thing that makes native focus exist for keyboard at all — the plan's reliance on it is confirmed correct.
- **The funnel never runs in combat, overland, placement, or party management.** In those states native index focus does not exist for anyone, controller included. The selection join (WP4) covers everything the funnel serves: menus, dialogue, sheet lists, character/attribute sheets, attribute editor plus/minus (natively navigable — the March "image-only" claim was wrong), feat trees (fully navigable 2D, also wrongly tiered in March), sliders, inventory main/secondary grids (column-cursor navigable — March claim wrong), and popups including the spell-learn grid.
- **The combat ability/spell/consumable selector grids are the flagship gap — with a dormant native fix.** `UIAbilitySelectorGrid` implements full 2D scrollable-element navigation that nothing wires in (combat GUIControls never override `getControllerScrollableList`, and combat states never call the funnel). The remediation is port-first: a patch that returns the grid from `getControllerScrollableList` and drives the funnel in combat states — the game's own mechanism, switched on. No mod graph needed.
- **Combat targeting, placement, movement preview, and all overland interaction are mouse-position-plus-confirm.** No tile cursor exists natively. This is the RW3-kit territory (mod tile cursor driving the game's own mouse position, exact-offset phrasing, AoE census) and belongs to the combat proposal, not the baseline WPs.
- **Small mouse-only islands:** worn-equipment grid, merchant service buttons, party-management portraits, overland spell-target portraits, weapon swap (native toggle-key alternative exists), sheet tabs (native LB/RB/Alt alternative exists), main-menu button (Esc exists). Each becomes a gap-ledger row: wire natively where the game's own structures allow, small review layer otherwise, JUSTIFIED-DROP where a native alternative already covers the function.
- **Display-only surfaces** (AP counter, initiative list, portrait HP/status, gold/weight, points-remaining, the secondaryDescription combat/hover line): speech from content/state joins, not navigation — WP5 catches several via existing setters; the rest are combat-proposal readouts.
- **ui_graph verdict:** not the backbone. SKALD has a native index system nearly everywhere widgets exist, and the channel law forbids a second focus where the game has one. The uncovered surfaces are either native-wirable (selector grids), tile-spatial (RW3 cursor idiom), or tiny button islands. ui_graph stays in the toolbox for any stubborn multi-widget surface (party management is the only candidate so far); if adopted there, zlib license and lineage credit travel with the sources.

**WP10 — The review layer: terse focus + navigable panel buffer (spec APPROVED by owner 2026-08-16, designed live across the day's rides; BUILT same day at owner direction — ride-verify pending; the terse-tier per-source defaults remain open calibrations, auto-read behavior unchanged this build).** Supersedes the §5 keymap note reserving bare arrows for a review layer: bare arrows stay on their native bindings permanently; review borrows them only inside its toggle.

*Problem.* The game has one description pipeline (`getFullDescriptionAndHeader` → panes/tooltips) with no terse/verbose distinction — the visual pane IS the drilldown: glanceable, ignorable. Speech can't ignore, so every focus move drags the full text behind it (worst: inventory `printComparativeStats`, 40–80 words per grid step; CC class pickers, multi-paragraph blobs). The fix is one architecture, not per-screen hacks: terse at focus, the panel always one gesture away.

*Terse tier.* Per-source terse composition at focus. Comparison colors transcode to words PER STAT ("Soak: 3, better") — the green/red is the game's own display and the only carrier of better/worse; aggregate verdicts ("better than equipped") are mod-computed judgment and stay forbidden (no-tactic-computing). Open calibration: a trailing "details" particle when panel text exists.

*Sectioning engine.* The game's markup grammar is the schema — no per-screen curation: `HEADER_TAG` runs open sections and carry the game's own section names; contiguous `ATTRIBUTE_NAME_TAG`/`ATTRIBUTE_VALUE_TAG` pair runs form a stats section whose elements are the individual pairs; `\n\n` splits prose sections whose elements are sentences. Composition is lazy at keypress time — the "buffer" is two cursor ints (section, element), reset on focus change; no text is ever cached, so no staleness and no mirror. Counts trail ("section 2 of 4").

*Two doorways, one engine.* (1) Stateless nav cluster, always live in every state, combat included: **Home/End = section walk, PgUp/PgDn = element-within-section**. (2) The R toggle for cluster-less keyboards: enters a review state where **Left/Right = section walk, Up/Down = element-within-section** (horizontal = structure, vertical = drill — identical cursors to the cluster). R is conditional (owner: good enough for now); "/" stays Stop, untouchable.

*Input classes inside the toggle.* Navigation (W/S/A/D): exit review, then act. Activation (Z, X, Enter, Space, numbers, U/I): **eaten at the choke point — review closes, "Closed." + the focused element's terse line re-anchors, nothing fires.** The virtual mouse never moves during review, so a click from inside the buffer would be a blind click on an element the player long stopped attending; the eat makes blind confirms impossible by construction. The physical mouse is exempt (a real click acts on the visibly hovered thing — sighted co-use stays coherent). Dismissal (R, Esc, Backspace-as-B): exit with the press swallowed so Esc closes the buffer, never the menu behind it.

*State discipline.* One boolean; arrows-only capture while set; six exits (toggle, dismissal, activation-eat, focus change, state-clock transition force-clear, text-entry gate) converge on a single exit routine. Key swallowing rides one choke point — postfixes on `SkaldIO.getKeyPressed`/`getKeyHeldDown`/`getKeyUp` — so the game goes blind to captured keys atomically; the only raw-Input arrow consumer (console history) sits behind the text-entry gate where review suspends anyway.

*Modifier survey (recorded so it is never relitigated).* Both Alts = state-carousel press-actions; both Ctrls = ability/filter-shift press-actions (game-reserved); LeftShift = Highlight, held-passive (usable-with-flicker fallback only); RightShift = natively dead — the chord design it enabled was superseded by the R toggle; "/" = mod Stop. Free-and-dead pool for future keys: R (taken by the toggle), B H K M N O P V Y, F3/F4/F6-F8/F10-F12, Insert/Delete, `; ' \`.

*Streams during review.* No suppression: the per-source diff already silences unchanged hover repaints, and a hover text that genuinely changes mid-review speaks honestly. World streams (barks, combat log) stay live — a reading mode never makes the game quieter than it is.

*Per-source verbosity defaults (open calibration docket, ruled per ride):* journal/books/dialogue keep full auto-read (being read to is the screen); inventory/spells/abilities go terse; the settings quote-sample and its template kin are per-class rulings.

*Acceptance.* An item tooltip and a spell panel navigate fully through both doorways with identical section/element structure; the cluster works mid-combat; no input from inside the toggle can fire a game action; the review flag cannot survive a state transition; bare arrows behave natively whenever the toggle is off.

**WP11 — The overland cursor: mouse-identity browsing, category scans, and the catalog list (spec owner-designed 2026-08-16 across the survey conversation; adversarial source-review pending before build).** Companion ground truth: `docs\overland-survey.md`. Design intent, owner's words: a bookmarking system and pathfinding that never forces pathfinding on the player — they stay in control of their heading and remain geographically aware all the way through.

*Doctrine.* The cursor IS the game's virtual mouse — one position, owned by the game; the mod moves it and speaks it. No mode for browsing (arrows coexist with WASD party movement), no mirror, no cached text: every utterance composes at keypress from game truth (the WP10 lazy idiom). Z and X keep their native meanings everywhere (click = path/attack/interact; right-click = inspect tooltip). Visibility contract: speak a tile iff `isSpotted()` (the game's own spoiler gate — non-regrow maps keep remembered terrain spotted natively; owner-ruled 2026-08-16: no spottedOnce tier); identify an occupant iff illuminated/spotted, else "something unseen" (that IS rendered); a spotted tile failing the live viewshed test (party-tile distance vs `viewDistance` + `testLineOfSight`) carries a trailing out-of-view qualifier.

*Prerequisite (owner action at next launch):* rebind the four alt-movement bindings ("Move N/S/E/W 2" — natively the arrow keys, SKALDKeyBindings.cs:132-135) to None in Settings → Key Bindings, freeing bare arrows overland.

2. *Category scans (modeless keys, overland only, text-gate suspended; while review or list is open they exit-then-act).* **H** hostiles · **N** neutrals · **B** loot (containers, ground-item tiles, pickups) · **O** objects (doors, interactables, workbenches, beds, light sources, inspectables, skill-check props, named scenery) · **M** exits (map-edge exits — one synthetic entry per edge direction at the nearest passable border tile; warps; nested-map entrances; ships) · **P** reverse. Each prop belongs to exactly one category (precedence Exits > Loot > Objects); hidden props excluded until the game reveals them; unseen-icon tiles ride the tail of the Hostiles ring as "something unseen" (caution bias — ride-revisable). **No scan-index state:** a scan key jumps to the nearest member if the cursor isn't on one, else to the next-farther member, wrapping; P steps nearer. Enumeration = viewport sweep with side-effect-safe reads at keypress; distance = the game's own Manhattan metric; counts trail.

Up/Down = entities within category (no wrap; edge lines), Left/Right = category switch (speaks category + count, lands on its nearest member). Every landing zips the mouse and speaks "name, offset, i of N" — the trailing counter is the audible mode marker; panel = the entity's inspect text. Order freezes at open (no reshuffling mid-browse), distances compose live, entities re-validate at speech time ("gone" honestly). **Z closes the list and clicks natively** — the mouse is on the selection by construction, so no activation-eat is needed (the WP10 blind-click hazard is impossible here); native click semantics apply verbatim, including the game's own click-cancels-course-first behavior. **WASD stays live (owner-ruled): the beacon** — each committed party step while the list is open re-speaks the tracked entity's offset, terse; the beacon doubles as the mode reminder. Exits: K/Esc/Backspace swallowed → "Closed." + cursor line; R closes the list silently (review opens on the landed panel); state-clock transition force-clears; text-entry gate suspends. Mutual exclusion with the review toggle.

*Amendments from the adversarial source review (2026-08-16 — design survived; all ten A-list items resolved, seven findings folded in):*
- **The latch, not the nudge (K1/K6/A1-residual):** any physical-mouse pixel motion zeroes the virtual offsets every tick (SkaldIO.cs:438-443), every popup snaps the virtual mouse to its buttons under forced controller (PopUpBase.cs:34-44), and a plugged-in physical controller drifts the cursor via the RIGHT stick with no dead zone. So the cursor is a per-tick RE-ASSERTED latch on the held tile — suspended while a popup/cutscene is up (OverlandState stops updating then; mouseTile goes stale) and re-seated when it clears, and on resolution change. Read-back verification must check mouseTile freshness (it has exactly one overland writer, OverlandState.cs:372, and goes stale whenever setMouseInput is skipped).
- **Arrows freed by accessor patch, not player rebind (K2):** the rebind screen rejects None (SKALDKeyBindings.cs:149-151). Instead: postfixes on `getUpAltKey/getDownAltKey/getLeftAltKey/getRightAltKey` → KeyCode.None. Their complete consumer set is eight OR-merged reads inside SkaldIO — surgical, zero collateral, no owner action needed.
- **Happy finding (A1):** the game's virtual cursor is driven by the RIGHT joystick axes; our WASD feed touches only the left-stick accessors — WASD can never fight the arrow cursor. Confirmed safe.
- **Course join moves to Party methods (K4):** Character-level fires once per member and clear fires even with an empty course (and on every right-click). Patch `Party.setNavigationCourse`/`Party.clearNavigationCourse`, gate "Stopped." on nodes-existed-beforehand, and speak a path-failure line when a click/Z sets no course (findPathToMouseTile returns true regardless).
- **Tooltip discipline (K5/A7-conflict):** the inspect tooltip sits under the cursor, never loses hover, and silently swallows the next Z; a tall tooltip's scrollbar also captures held arrows (binding-independent, SkaldIO.cs:1093-1098). `ToolTipPrinter.clearToolTip()` before any synthesized click and on every nudge.
- **No click-to-attack promise at range (K3, native):** a course is cancelled when enemies NEWLY enter the nearby set mid-walk (rising edge, OverlandState.cs:161-164) — clicking a distant hostile can halt short. Already-visible hostiles path-and-engage as designed. The "Stopped." line carries the halt honestly. Related native two-press frictions, voiced not fixed: WASD's first press during auto-walk cancels rather than moves; Z during auto-walk cancels rather than re-targets.
- **Edge-click hazard voiced (K7, native):** testMouseExitId uses a different, rim-less RoundToInt conversion — a Z with the party on a border row/column and the cursor on the near half of the screen can arm a map transition on arrival. Native mouse behavior; the map-mount announces via the state/header joins; noted for rides.
- **Out-of-view test corrected (A8):** "in sight now" = Euclidean distance ≤ 5.99 from ANY party-member tile + the game's own `testLineOfSight` (intermediate tiles only) — computed per member via `getEachTileOccupiedByPlayers` semantics. `isSpotted()` alone means "known", not "in sight" (no-regrow maps keep explored terrain spotted): the qualifier attaches to spotted-but-not-in-sight, exactly as ruled.
- **Nudge mechanics (A3/A9):** nudges stay in Plugin.Update (same-frame Z then clicks the NEW tile — no settle needed; moving the nudge after setMouseInput would break this); aim at tile CENTERS (right rim's 0.95 cutoff only kills a rim column; centers are always expressible); gate nudges on `isScrollReady()` or read scrollX/Y by reflection mid-slide; derive positions from the viewport accessors, never the party position (deadspace decouples them); key-repeat keyed to frames, not ticks.
- **Mode hygiene (A10):** the list gets its own flag (never the grid-modal flag — that would kill WASD), mutual exclusion with ReviewLayer.Active, K added to the swallow set only while the list is open. X while browsing: fine (it cancels a course — gated "Stopped." makes that honest), holding X flips the game's highlight mode (cosmetic). The sweep's readers are confirmed side-effect-safe (the renderer already runs the same reads per frame over more tiles); never call `setSpotted()` or `getAccessibleTilesFromParty()` from a reader (both mutate).
